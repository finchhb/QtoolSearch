# Подбор токарных пластин v8.4 (Rinscom / qtool.ru)

**Как работает.** Ответ всегда формирует внутренний парсер ISO 1832 (материал → группа ISO по таблице «Марки по ISO», форма, размер, радиус,
стружколом, наличие, цена, ссылки). LLM (любой OpenAI-совместимый API) только проверяет параметры; без неё всё работает на одном парсере.
Она подключается: если не распознан материал, нет кода пластины и запрос описан свободным текстом; если найдено 0 позиций или фильтры пришлось ослабить;
если не хватает ≥2 ключевых параметров (нужны точные вопросы); плюс в 15% остальных запросов (`AUDIT_SAMPLE_RATE`) для контроля парсера.
LLM возвращает JSON с поправками; применяются только значения из белых списков и только для параметров, которые парсер не нашёл.
Расхождения по найденному парсером — примечание в ответе и запись в `data/review_log.jsonl`.
В интерфейсе у каждого ответа плашка: «⚡ Внутренний парсер ISO 1832» или «🔍 Проверено LLM-верификатором».
Если проверка была нужна, но API недоступен (ошибка, лимит, пауза) — предупреждение «проверка LLM сейчас недоступна». Без ключа всё работает на одном парсере.

## Запуск на Windows
1. Распаковать, запустить `run.bat` (Python 3 уже есть — берётся он; нет — скачается портативный).
2. Откроется http://localhost:8000. В шапке чата кнопки «Источник», «Правила», «LLM» (видны только при локальном запуске) ведут в админку: http://localhost:8000/admin.
3. Для LLM-проверки: выбрать провайдера (см. ниже), указать адрес, ключ и модель в админке (блок «LLM-верификатор») или в `.env`.

## Что проверить на качество
`eval.bat` (или `python eval.py`): точность парсера по `data/test_dataset.json`. Положи `data/queries.xlsx`
(колонки «Запрос» и «Эталонный артикул») — получишь hit@1 / hit@5. Ключ `--llm` — прогон с проверкой LLM (нужен ключ).
Свои правила материалов (лист «Марки сплавов по ISO») — в `data/materials.csv`: `pattern,iso,note`; `note` показывается в ответе, когда сработало правило (например, «зависит от состояния заготовки»).

## Цены и каталог
- Цена по запросу берётся из колонки «Цена по запросу» выгрузки qtool.ru (999.9 и 0 — заглушки, показываются как «цена по запросу»).
- USD/EUR/GBP/CNY пересчитываются в рубли по курсу ЦБ (кэш `data/rates.json`, обновление раз в 12 ч). Нет курса — показывается исходная валюта.
- Поле «Активность» из выгрузки сохраняется как `active`; `ADVISOR_EXCLUDE_INACTIVE=1` скрывает позиции с N.
- Источники и пересборка каталога — в админке; вручную: `python build_catalog.py data/price_sale.xlsx data/catalog_rinscom.csv`.

## Публикация на сайте (кратко)
Файлы в `deploy/`: `.env.example`, `tool-advisor.service` (systemd), `nginx.conf` (ai.qtool.ru, админка по IP), `embed-snippet.html`
(кнопка и окно чата на qtool.ru). Режим `ADVISOR_MODE=public`: админка только по `ADMIN_TOKEN`, ключ LLM только из переменной окружения LLM_API_KEY,
лимит запросов на IP, история диалога отдельно для каждого посетителя, CORS/iframe только для `ALLOWED_ORIGINS`.

## Режим работы по умолчанию
Только внутренний парсер, без LLM (LLM подключается по желанию, см. ниже). Источник — обе таблицы сразу, Rinscom.com + qtool.ru (`ADVISOR_DEFAULT_SOURCE=qtool|rinscom` меняет).
Одна и та же пластина из разных магазинов и складов показывается ОДНОЙ карточкой с блоком «Предложения» (цена и остаток по каждому магазину, суммарный остаток).
«Обновить прайсы» (админка → источник) скачивает обе таблицы, пересобирает каталоги и оставляет режим «оба».
**Цены в валюте:** у части позиций qtool.ru в выгрузке стоит USD/EUR/CNY, но числа сопоставимы с рублёвыми ценами Rinscom (вероятно, ошибка валюты в выгрузке).
Поэтому пересчёт по курсу выключен: показывается «цена уточняется на сайте (в выгрузке: 408.00 USD)». Включить пересчёт: `ADVISOR_CONVERT_FX=1`.

## Обучение парсера на примерах
Под каждым ответом (в локальном режиме) есть блок «🎓 Обучить парсер»: он показывает, как парсер понял запрос, и даёт ввести правильную группу ISO, вид обработки,
правильные артикулы и комментарий. Пример сохраняется в `data/training_examples.csv` (разделитель «;», открывается в Excel) и дальше используется:
1. при точном повторе запроса парсер применяет ISO и вид обработки из примера, рекомендованные артикулы ставятся первыми, в ответе пометка «Применён пример технолога №…» и комментарий;
2. после сохранения предлагаются «подозрительные» марки из запроса: отметил — они дописываются в `data/materials.csv` как правила, и парсер узнаёт марку в любых запросах;
3. `python eval.py --training` (или `eval.bat --training`) прогоняет всю таблицу через парсер БЕЗ подсказок и показывает, где он ещё ошибается (ISO, обработка, попадание эталонного артикула в топ-1/топ-5).
Таблица и управление ею — в админке, блок «🎓 Обучение» (есть скачивание CSV). Отключить применение примеров: `TRAINING_DISABLE=1`.
Ограничение: примеры применяются при ТОЧНОМ совпадении запроса (после нормализации регистра, ё, латиницы/кириллицы и знаков); обобщение на похожие запросы идёт через правила материалов (п. 2).

## Справочники компании (методичка Дескар, таблица Келит)
`python import_docs.py <папка с xlsx>` читает листы по названиям (имена файлов любые) и создаёт:
- `data/materials_iso.csv` — марки заготовок по ГОСТ → группа ISO (лист «Марки сплавов по ISO», 382 марки; нержавеющие 52, в т.ч. 03Н17К10В10МТ-ВД и ЭП836-ВД).
  Латиница в марках (20X13) понимается. Голые числа («45») не используются — только «сталь 45», «Ст45». Свои правки — в `data/materials.csv`.
  Исправление в таблице: блок «Чугуны» помечен там как P, по ISO это K — импорт ставит K.
- `data/grades_docs.csv` — сплавы → ISO: таблица аналогов Deskar/INTOOL/ZCC-CT (классы P05…K40) и описания Kelite (53 сплава).
После импорта пересобери каталог (админка → «Скачать прайс» или `python build_catalog.py data/price_sale.xlsx data/catalog_rinscom.csv`).
Правила: для Kelite справочник описывает сплав целиком и заменяет прежний ISO; для ZCC-CT/INTOOL таблица аналогов содержит только P/M/K, поэтому они берутся из справочника, а S/N/H остаются прежними;
для Deskar богаче лист «Сплавы» (уже в `grades.csv`), справочник используется только для сплавов, которых там нет. Отключить: `GRADES_DOCS_OVERRIDE=0` при сборке.
В ответе по P/M/K появляется строка «По методичке…»: какие сплавы рекомендованы для группы и вида обработки и сколько позиций в наличии.
Что изменилось в каталоге при первом импорте — `data/docs_vs_catalog_report.csv` (367 из 4160 позиций в наличии).

## Какой LLM подключить
**OpenRouter не подходит:** с 27.06.2026 он не принимает запросы из РФ (платежи закрыты с 11.05.2026).
Все варианты ниже подключаются без правок кода — только `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODELS` (примеры в `deploy/.env.example`).

| Вариант | Адрес и доступ | Стоимость (по открытым прайсам, сверь перед использованием) |
|---|---|---|
| Yandex AI Studio | `https://ai.api.cloud.yandex.net/v1`, ключ + ID каталога; модели YandexGPT, gpt-oss-120b/20b, семейство Qwen | YandexGPT Lite ≈ 0,20 ₽ за 1000 токенов |
| Cloud.ru Foundation Models | OpenAI-совместимый API, 20+ моделей (Qwen, GLM, DeepSeek, gpt-oss), оплата по факту | gpt-oss-120b: 61 ₽ за 1 млн выходных токенов; бесплатный период закончился 31.10.2025 |
| MWS GPT Model Hub | OpenAI-совместимый API | gpt-oss-120b: 13,42 ₽ / 54,90 ₽ за 1 млн входных/выходных токенов (с НДС) |
| Своя модель | Ollama / llama.cpp на сервере или ПК, `http://localhost:11434/v1` | 0 ₽ за токены; нужно железо (см. ниже) |

Один запрос проверки — порядка 700 входных и 100–600 выходных токенов (reasoning-модели тратят больше), то есть копейки: 1000 проверок в день ≈ 40 ₽ на MWS.
Точные цифры покажет `eval_llm.py` (выводит средний расход токенов).

**Выбор по цифрам:** `python eval_llm.py` (нужен ключ) прогонит 75 фраз из `data/llm_benchmark.json` и покажет точность парсера, LLM и их связки,
долю невалидных JSON, ошибки API и задержку. Эталоны в файле — черновик: технолог должен поправить спорные строки.

**Своя модель:** для Qwen2.5-14B/Qwen3-14B в 4-битном виде нужно ~10–12 ГБ видеопамяти или ~16 ГБ ОЗУ (на CPU заметно медленнее: поставь `LLM_TIMEOUT=60`).
Лицензии моделей и скорость на вашем железе не проверялись — убедись сам.

**Без LLM:** парсер сам определяет материал и вид обработки; нераспознанные запросы копятся в `data/unrecognized_queries.jsonl`
(в админке — «unrecognized_last»): добавляй строки в `data/materials.csv`, и словарь растёт.

## Приватность
Запросы клиентов уходят провайдеру LLM. Персональных данных в них быть не должно; у Yandex есть настройка отключения логирования запросов,
у Cloud.ru внутренние модели не сохраняют данные, а внешние маршрутизируются зарубежным провайдерам — выбирай внутренние.
Проверка добавляет до `LLM_TIMEOUT` секунд к ответу в сложных запросах.

## Ограничения
- Токарные пластины: резьбовых и канавочных позиций в каталоге qtool.ru сейчас нет.
- Адрес файла прайса qtool.ru в `build_catalog.py` содержит дату (`..._03.11.26.xlsx`); для автообновления нужен стабильный адрес или выгрузка из 1С/сайта.
- Подбор справочный; перед заказом сверять карточку товара.
